# Good First Issues

These are real, bounded backlog items rather than placeholder contribution
counts. Claim one by commenting with the smallest intended change and the checks
you can run. A maintainer confirms scope before implementation begins.

| Issue | Small outcome | Primary evidence |
| --- | --- | --- |
| [#10](https://github.com/sheryloe/pocketforge-relay/issues/10) | Return keyboard focus after deletion confirmation closes | PWA contract test plus keyboard review |
| [#11](https://github.com/sheryloe/pocketforge-relay/issues/11) | Publish retained SHA-256 on Actions downloads | Authenticated HTTP tests |
| [#12](https://github.com/sheryloe/pocketforge-relay/issues/12) | Validate all existing pilot-report evidence fields | Boundary tests and both recorded reports |
| [#13](https://github.com/sheryloe/pocketforge-relay/issues/13) | Protect container/live-Actions translation claims | EN/KO/JA semantic marker tests |
| [#14](https://github.com/sheryloe/pocketforge-relay/issues/14) | Keep remote success non-terminal until evidence finalizes | Manager, HTTP, and PWA transition tests |

All five issues preserve the project boundary: no arbitrary shell input, no
invented execution evidence, and no weakening of approval, data, or artifact
verification. They are invitations to contribute, not evidence of external
contributors or adoption.
